# Chapter 03 - PLL

## Overview

A PLL, or Phase-Locked Loop, is a clock generation block inside an FPGA.

The board usually provides one fixed input clock, such as 50 MHz. A PLL can generate the clock frequency that the design actually needs.

Topics: clock input, PLL output clock, frequency multiplication, frequency division, `locked` signal, clock-based practice.

## Design

A PLL takes an input clock and produces one or more output clocks.

```text
Board Clock
   clk_in
     |
     v
+---------+
|   PLL   |
+----+----+
     |
     +--> clk_out
     +--> locked
```

The `locked` signal tells the design that the PLL output clock is stable.

In real hardware, the system should usually stay in reset until `locked = 1`.

---

## Signal Table

| Signal | Dir | Description |
|--------|-----|-------------|
| `clk_in` | in | Clock from the FPGA board |
| `rst_n` | in | Active-low reset |
| `clk_out` | out | Clock generated by the PLL |
| `locked` | out | PLL is stable when this signal is high |

---

## Block Diagram

```text
          +---------+
clk_in -->|   PLL   |--> clk_out
rst_n  -->|         |--> locked
          +---------+
```

Example usage:

```text
clk_out -> LED blink counter
locked  -> reset release
```

---

## Behavior

The PLL changes the input clock into another clock.

Examples:

| Input Clock | PLL Output Clock | Example Use |
|-------------|------------------|-------------|
| 50 MHz | 100 MHz | Faster internal logic |
| 50 MHz | 25 MHz | VGA pixel clock practice |
| 50 MHz | 10 MHz | Slower experiment clock |
| 50 MHz | Multiple clocks | Designs with different clock domains |

Important idea:

```text
locked = 0  PLL output is not ready
locked = 1  PLL output is stable
```

## Simulation

PLL blocks are usually vendor-specific FPGA IP.

That means a real PLL is not normally written as pure Verilog like the previous chapters. In practice, you generate it using the FPGA tool, for example:

```text
Intel Quartus     -> ALTPLL / PLL IP
AMD Xilinx Vivado -> Clocking Wizard / MMCM / PLL
Lattice tools     -> PLL primitive or IP generator
```

For simulation, there are two common approaches:

| Approach | Use Case |
|----------|----------|
| Vendor simulation model | More realistic PLL simulation |
| Simple Verilog clock model | Beginner practice and waveform learning |

For this learning chapter, the first goal is to understand the signals:

```text
clk_in
clk_out
locked
reset
led
```

## Waveform

When practicing PLL behavior, inspect these signals in GTKWave:

```text
clk_in
clk_out
locked
rst_n
led
```

Expected waveform idea:

```text
rst_n   starts low or is pressed low
clk_in  keeps toggling
clk_out starts after PLL model is ready
locked  becomes 1 after the PLL stabilizes
led     starts blinking only after locked = 1
```

## Practice

### Practice 1 - Understand the Board Clock

Find the input clock frequency of your FPGA board.

Examples:

```text
25 MHz
50 MHz
100 MHz
```

Write it down before generating a PLL.

---

### Practice 2 - Generate One PLL Output Clock

Use your FPGA vendor tool to create a PLL.

Try this simple target:

```text
Input clock:  50 MHz
Output clock: 25 MHz
```

If your board uses a different input clock, choose a simple divided clock that your tool accepts.

---

### Practice 3 - Blink an LED with the PLL Clock

Reuse the LED blink idea from Chapter 01, but change the clock source:

```text
Chapter 01:
Board clock -> LED blink

Chapter 03:
Board clock -> PLL -> PLL clock -> LED blink
```

The reset idea should be:

```text
if locked = 0:
    keep LED logic in reset

if locked = 1:
    allow LED logic to run
```

---

### Practice 4 - Change the PLL Output Frequency

Change the PLL output clock and observe the LED blink speed.

Example:

```text
clk_out = 25 MHz  -> LED blink counter runs slower
clk_out = 100 MHz -> LED blink counter runs faster
```

This helps connect clock frequency with circuit behavior.
